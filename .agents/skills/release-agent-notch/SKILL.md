# Release Agent Notch

Полный выпуск: проверенный исходник → локальные ZIP/DMG и подпись → публичный GitHub Release с рабочей лентой → Homebrew cask → проверка установленного приложения, если она входит в запрос.

## Перед запуском

Прочитай корневой `AGENTS.md` и [порядок выпуска](references/workflow.md). Все команды выполняет агент; пользователь подтверждает только требуемые системные диалоги или недостающие разрешения.

Установи стабильную версию из запроса или подготовленной секции `CHANGELOG.md`. Если версия не определена, уточни её. В первом сообщении назови версию и затрагиваемые места:

- `Forichok/Agent-Notch`: исходник, тег и публичный Release;
- `Forichok/homebrew-tap`: публикация `Casks/agent-notch.rb`;
- `/Applications/Agent Notch.app`: замена установленной копии, если запрошена.

Используй уже данное разрешение в текущей задаче. Разрешение на создание этого скилла, подготовку архивов или выпуск только в первом репозитории не разрешает остальные записи. Если для tap разрешения нет, подготовь точный diff и запроси только его публикацию, продолжая остальные разрешённые шаги. Скилл не даёт постоянного разрешения на будущие релизы.

## Выполнение

1. Подготовь и проверь версию, changelog и свежий исходник согласно `AGENTS.md`. Не меняй чужой checkout. До сборки зафиксируй полный SHA; артефакты должны содержать этот SHA.
2. Запусти `sh scripts/prepare-release.sh "$version"` в **PTY**. macOS может ждать подтверждения `generate_appcast`. Объясни: ключ подписывает архив издателя; получателям приложения доступ к нему не нужен. Пароль вводится только в системном диалоге. Отказ отменяет подпись и публикацию; ключ не экспортировать, не менять и не загружать в GitHub.
3. Если остановилась только подпись, продолжи по разделу восстановления в workflow. Не пересобирай неизменившийся проверенный исходник. После возобновления создай отсутствующий cask и проверь весь комплект.
4. Выполни локальный аудит и независимое ревью. Обновлять можно только черновик; существующий публичный релиз и его тег не перезаписывать. Загрузка архивов в draft ещё не означает выпуск.
5. Опубликуй все проверенные файлы, затем проверь **публичные** URL без авторизации через `scripts/release_audit.py` этого скилла. HTTP 404, неверная подпись или несовпадение версии блокируют дальнейшую установку и сообщение об успехе.
6. Опубликуй разрешённое изменение tap и проверь опубликованный cask тем же аудитом с `--check-tap`.
7. Если запрошена установка, выполни правила `AGENTS.md` для свежести, Prompts, настроек и Keep awake. Установи именно скачанный и проверенный публичный bundle, сверив исполняемый файл и helper. Нажми ручную кнопку в настоящей установленной копии.

**Режим обновления неизменен:** только по кнопке; загрузка, установка и перезапуск с подтверждением. Не включай фоновые проверки и не отключай проверку подписи ради выпуска.

## Результат

Сообщи ссылку на публичный релиз, состояние cask и установленной копии. Последняя строка — где и как проверено. Черновик, локальная сборка, симуляция и зелёные unit-тесты не доказывают публичную доступность. При незавершённом шаге укажи `NOT verified` и конкретную причину.
