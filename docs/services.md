# Сервисы

«Настройки → Сервисы» запускают и настраивают локальные программы, у которых есть манифест для Agent Notch. Раздел ничего не знает о конкретной программе: форму, команды и файлы даёт манифест, строки состояния — форма файла состояния. Первым сервисом подключён Гоша (Discord-бот, `~/Documents/Projects/chedrik`), его контракт — `docs/agent-notch.md` в его репозитории.

## Как добавить

«Добавить сервис…» → папка, в которой лежит `ops/agent-notch.json` (или `agent-notch.json` в корне). Приложение читает манифест и показывает имя сервиса, каждую команду с аргументами, какие из них получают настройки и какие файлы читаются для состояния и логов. Сервис добавляется только после «Добавить». Если файл манифеста потом изменится хоть на байт, раздел покажет «Манифест изменился» и ничего не запустит, пока изменения не подтвердят снова.

## Манифест, версия 1

| Поле | Что это |
|---|---|
| `manifest` | версия схемы, `1` |
| `id` | `^[a-z0-9][a-z0-9._-]{0,63}$`; имя записи в связке ключей |
| `name`, `description` | имя в списке и строка под ним |
| `cwd` | папка, из которой запускаются команды, относительно папки сервиса; по умолчанию `.` |
| `settings` | `{ "via": "fd", "fd": 3 }`: настройки идут JSON-ом в дескриптор `fd` (3–9) |
| `fields[]` | поля формы |
| `commands` | имя → `{ run, config?, json?, label?, timeout? }` |
| `status` | файл состояния |
| `logs` | имя → файл лога |

Пути `status` и `logs`: `~/…` (домашняя папка), абсолютный путь или путь относительно папки сервиса. Неизвестные поля верхнего уровня пропускаются.

### Поля

| Свойство | Что это |
|---|---|
| `key` | имя настройки, `^[A-Za-z_][A-Za-z0-9_]{0,63}$` |
| `label`, `help`, `placeholder` | подписи в форме, одной строкой |
| `type` | `string`, `secret` или `select` |
| `required` | без значения Start и Restart недоступны |
| `pattern` | регулярное выражение, ищется в значении (как `RegExp.test`); якоря `^…$` ставит сам манифест |
| `default` | значение по умолчанию; у `secret` его нет, у `select` со списком оно должно быть в списке |
| `options` | для `select`: `values` — `[{ value, label }]`, или `command` — команда из `commands` с `json: true`, которая печатает JSON-массив |

У `options.command` ещё есть `value` и `label` (имена полей объектов в ответе), `enabledWhen` (поле, которое должно быть `true`, чтобы вариант можно было выбрать) и `sets`: что записать в другие настройки при выборе, например `{ "claude": { "CLAUDE_BIN": "path" } }`. Поля объектов `method` (или `detail`) и `version` показываются под выбором, `login` — как подсказка для варианта без входа. Приложение не запускает `login`: это не команда манифеста.

### Команды

`run` — массив аргументов без оболочки. `run[0]` — программа внутри папки сервиса, относительно `cwd`; после разрешения ссылок она должна остаться в папке. `config: true` — команда получает настройки. `json: true` — stdout — JSON. `timeout` — секунды, 1–3600, по умолчанию 180. `label` — подпись кнопки; без неё у `start`, `stop`, `restart`, `status` и `check-pc` есть свои.

Кнопки раздела: `start`, `stop`, `restart`, `status` и «Проверка» для `check-pc`. Start и Restart требуют заполненных обязательных полей; остальные команды с `config: true` получают то, что заполнено, поэтому проверка работает и до заполнения всей формы. `check-pc` печатает `{ ok, url, healthMs, latencyMs, error }`; если JSON нет, показывается последняя строка stderr.

## Как запускается команда

- Перед каждым запуском манифест читается заново и сверяется с подтверждённым (SHA-256 текста). Программа ещё раз разрешается и должна лежать в папке сервиса.
- Манифест, папка сервиса, `cwd` и программа должны принадлежать пользователю (или root) и не быть доступными на запись группе и остальным.
- `posix_spawn`: stdin — `/dev/null`, stdout и stderr — каналы приложения, настройки — канал на дескрипторе из `settings.fd`. Объект пишется в канал целиком до запуска, конец приложения закрывается. Остальные дескрипторы приложения закрыты (`POSIX_SPAWN_CLOEXEC_DEFAULT`).
- Настройки не попадают ни в окружение, ни в аргументы, ни на диск.
- Окружение: `HOME`, `USER`, `LOGNAME`, `SHELL`, `TMPDIR`, `LANG`, `LC_ALL`, `LC_CTYPE`, `__CF_USER_TEXT_ENCODING` и `PATH`, который выдаёт оболочка входа пользователя (`$SHELL -l -c`). У приложения из Dock `PATH` — только `/usr/bin:/bin:/usr/sbin:/sbin`, а node и CLI обычно лежат в других местах. Ничего другого из окружения приложения сервис не получает: ни `CLAUDECODE`, ни ключей API.
- Команда работает в своей группе процессов; по тайм-ауту группа получает SIGTERM, через 3 с SIGKILL. Демон, который команда оставила держать её вывод, ждём не дольше секунды после выхода команды.

## Файл состояния

Приложение читает `status` раз в 2 секунды, пока открыт раздел. Сервис считается запущенным, если процесс `pid` жив и запущен не позже `startedAt` (плюс 5 с): так чужой процесс, получивший тот же pid, не выглядит сервисом. Кроме `pid`, `startedAt`, `updatedAt` и `lastError` каждый объект верхнего уровня становится строкой, по форме:

| Форма | Строка |
|---|---|
| `{ "online": bool, "servers": [{ "name", "answers" }] }` | в сети или нет, серверы; `answers: false` помечается |
| `{ "enabled": bool, "in": { "channelName", "guildName" } \| null }` | где сервис, «вне голоса», «выключен» |
| `{ "provider": string, "alive": bool }` | провайдер и готов ли он |
| `{ "ok": bool \| null, "url": string }` | работает, не работает, ещё не проверено |

Ключи `discord`, `voice`, `brain`, `tts`, `stt` идут первыми и подписаны по-человечески; остальные — по имени ключа.

## Секреты

Поля `secret` хранятся только в связке ключей входа: generic password, сервис `com.forichok.agents-notch.service.<id>`, аккаунт — `key` поля, доступ `WhenUnlocked`. После сохранения значение не показывается, раздел знает только, что оно есть. В UserDefaults (`services`) лежат папка, отпечаток подтверждённого манифеста, несекретные значения и «запускать вместе с приложением»; `ServiceEntry` отказывается записывать в себя ключ секретного поля. «Удалить сервис…» удаляет его секреты из связки ключей; файлы сервиса и запущенный сервис остаются.

Всё, что приложение показывает из сервиса (`lastError`, вывод команд, ошибка проверки, хвост логов), проходит маскировку: сохранённые секреты заменяются на `***`, где бы они ни встретились, а также всё, что похоже на токен Discord, ключи Anthropic, OpenAI и GitHub, `Bearer …`, `token=…`, `api_key: …` и пароль в URL.

## Проверка

- `scripts/test.sh`: `service*` в `Tests/CoreChecks` — разбор манифеста Гоши, отказ кривым манифестам, форма и JSON настроек, варианты из `providers`, канал в дескрипторе 3 на крошечном скрипте, который читает fd 3, утечка дескрипторов, окружение, тайм-аут, повторное подтверждение, файл состояния, проверка, хвост и маскировка логов.
- `AgentsNotch --snapshot-services <папка>` (из корня репозитория) рисует раздел на подставном сервисе на обоих языках: пустой, окно подтверждения, работающий и остановленный.
