## Где мы

Оркестраторы (Conductor, Vibe Kanban, cmux) решают другую задачу: они сами запускают агентов. Мы подключаемся к сессиям, которые уже идут.

Вывод: шириной (30 агентов), телефоном и маскотами нам не выиграть, это уже сделано. Остаётся одна позиция, которую никто не занял всерьёз: **честные локальные разрешения для Claude Code и Codex в ваших сессиях**. Без сети, только по клику человека, опасные команды красные, при молчании агент спрашивает в своём окне, а статус «доставлено» значит доставлено. Тему поддерживает спрос: в [anthropics/claude-code#43058](https://github.com/anthropics/claude-code/issues/43058) и [#94373](https://github.com/anthropics/claude-code/issues/94373) люди с десятками сессий не могут отличить «ждёт меня» от «закончил», а [#93672](https://github.com/anthropics/claude-code/issues/93672) жалуется на ложное «ждёт», пока работают фоновые сабагенты.

Сейчас эту позицию подрывает наш же код. Оба аудита нашли одно и то же:

- **Подключение.** «Подключено» горит, если в конфиге есть хоть одна наша команда (`HookInstaller.swift:52–62`). Включилось ли доверие в Codex `/hooks`, работает ли helper, пришёл ли хоть один хук, не проверяется. Мастера первого запуска нет.
- **Поиск сессий.** Codex ищется только в папках за сегодня и вчера (`LogScanner.swift:38–53`): тред трёхдневной давности, продолженный сегодня, после перезапуска приложения не виден. Чтение хвоста не переживает подмену или усечение файла (`LogScanner.swift:159–184`).
- **Доставка ответа.** После клика запрос сразу убирается, результат записи в сокет игнорируется (`HookServer.swift:64–66`). Поздний клик выглядит как ответ, хотя агент уже спросил в своём окне. Обратного отсчёта до 100 секунд в интерфейсе нет.
- **«Готово».** После 300 секунд тишины агент считается закончившим. Долгая команда Codex может получить тост «готово», а в тост может попасть чужой коммит, потому что берётся текущий HEAD (`SessionLog.swift:45–68`, `FinishSummary.swift:34–49`).
- **Удаление.** `brew uninstall --zap` при ошибке чистки конфига всё равно удаляет helper, и висячие хуки остаются (`packaging/agent-notch.rb:30–41`).
- **Документы.** README обещает «Разрешать всегда» и для Codex, но в коде эта ветка недостижима (`AlwaysRule.swift`, `Store.swift:170–184`). Вопросы и планы работают только у Claude. В CHANGELOG нет 0.4.0. ROADMAP.md называет продукт «Agents Notch» и запрещает «воркеров под родителем», которые уже выпущены.

Хорошая сторона: установка хуков сделана аккуратно (атомарная запись, симлинки, резервная копия, сокет закреплён за процессом), в ядре 122 проверки.

### Потом, три-шесть месяцев, если 0.5 и 0.6 сработали

- **Слой адаптеров для двух вендоров и набор фикстур по версиям** Claude и Codex (L). Сейчас `Vendor` — перечисление на два случая и около 60 ветвлений по коду. Изменения формата логов должны ловиться тестом, а не молча прятать агентов.
- **Пробный переход на Codex app-server** (M–L). Он сообщает `waitingOnApproval` и `serverRequest/resolved`, то есть настоящее подтверждение ответа, а не догадку по логам. Если для подключения придётся перезапускать чужие сессии, прекращаем.
- **Предпросмотр последствий** (M): перед `git push` показываем уходящие коммиты, перед `rm` — число файлов.
- **Конфликт файлов между агентами** (M): два агента правят один файл — предупреждаем.
- **Прогноз лимита** (S): «при таком темпе лимит кончится в 16:40».
- **Телефон и удалённые одобрения**: вернёмся к вопросу после 0.6.
- **Лимиты и расходы без притворства** (M): источник и возраст данных, «неизвестно» вместо нуля, дневной расход виден и без лимитов подписки.
- **Остальные вендоры** (L): владелец планирует их добавить после двух текущих. Первым кандидатом выглядит OpenCode: у него есть событие `permission.asked` и API ответа. У Gemini CLI разрешения только для наблюдения, у Cursor `ask` не применяется.

### Не делаем

- Оркестрацию, worktree и запуск агентов: это Conductor и cmux.
- Новые темы, маскоты, аналитику уровня биллинга, Intel, Windows и Linux в этом цикле.
- Всё из списка «Не делаем» в `ROADMAP.md`. Исключение — воркеры под родителем: остаются, строку из «Не делаем» вычёркиваем.

## Что берём у конкурентов

Второй раунд: восемь воркеров Codex прочитали исходники десяти конкурентов (Coucou, CodeIsland, Vibe Notch, CodexBar, MioIsland, CodexIsland, so-agentbar, cctop, Peekle, Code Island). Ничего не собирали и не запускали. Полные отчёты со ссылками на файлы и строки лежат в `scratchpad/swarm/*.md`.

**Лицензии.** Код Coucou, CodeIsland, CodexBar, CodexIsland, so-agentbar и Peekle под MIT: его можно брать, сохранив копирайт. Код Vibe Notch и cctop под Apache-2.0: можно брать с лицензией и NOTICE. MioIsland (CC BY-NC) и Code Island (GPL-3.0) годятся только как источник идей, код оттуда не копируем. Решение владельца: берём идеи и реализацию и переписываем под себя, целые файлы не копируем. Если фрагмент всё же переносится почти дословно, MIT требует сохранить строку копирайта.

**Главная находка.** Ни у кого нет подтверждения доставки ответа: у всех десяти клик убирает запрос до того, как агент что-то получил. Если мы это сделаем, у нас будет то, чего нет ни у кого.

**Где мы уже сильнее:** находим сессии Claude и Codex по логам без хуков, в том числе после перезапуска; дерево сабагентов; возврат плана с комментарием; структурные ответы на вопросы; проверка того, кто подключился к сокету; атомарная правка конфигов; контекст и стоимость; диплинки в приложения Claude и Codex; состояние «ошибки подряд»; 122 проверки. У CodexBar тот же провал с Codex старше двух дней.

### Потом

- Лимиты: источник, возраст и ошибка отдельно от последнего значения. Сброс считается наблюдённым, только когда пришли новые данные; сейчас мы ставим 0% по часам, и тест `UsageFixChecks` это закрепляет. Единицы по схеме, а не по величине: у CodexIsland 0,5% превращались в 50%. Источники: CodexBar, CodexIsland.
- Расходы: дедупликация по сообщению и запросу, учёт форков Codex, цены с уровнями длинного контекста (CodexBar).
- Описание возможностей вендора данными: формат конфига, события, таймауты, что умеет (наблюдать, отвечать на вопросы, одобрять). Источники: CodeIsland (код), Code Island (идея).
- Codex app-server как эксперимент. У CodeIsland есть реализация, у Code Island — список граблей: циклы запуска, взаимоблокировка на stderr, не было рукопожатия.
- Проверка обновлений: при первом запуске спросить один раз и запомнить ответ (so-agentbar).
- История диалога в карточке (Vibe Notch).

### Не копируем

- Тихую установку и «починку» хуков при каждом запуске. У CodeIsland такая «починка» возвращала хуки, которые пользователь удалил вручную (#182).
- Ожидание ответа 300 секунд или сутки, очередь всего на 5 запросов, выбор цели только по сессии, сопоставление tmux по кускам текста.
- Аналитику (у Vibe Notch Mixpanel) и сетевые квоты через OAuth и Keychain: они противоречат «без сети», а у CodexBar это вызывало до 24 запросов пароля Keychain.
- Схему одобрения с телефона по отпечатку без одноразового идентификатора запроса (Coucou).
- Любой код MioIsland и Code Island.

## Где отчёты разошлись

- **Другие вендоры.** Codex-аудит против в любом виде, рыночный отчёт Codex ставит их десятым пунктом при наличии спроса. Взял середину: адаптер ради двух нынешних вендоров, третий только по запросам.
- **Телефон.** Рыночный отчёт Claude: «или телефон, или прямое „нет намеренно“». Остальные советуют отложить. Владелец решил отложить до конца 0.6.
- **Sparkle.** Аудит Claude ставит его в топ-10, аудит Codex напоминает про обещание «без сети». Поставил в «Потом», включение по желанию.
- **Конкуренты.** Codex не нашёл Coucou и CodeIsland, а под именем Code Island показал другой репозиторий с 8 звёздами. Принял данные Claude, перепроверено через API.
