# План

Согласовано с владельцем 15 октября 2026 года. Позиция: честные локальные разрешения для Claude Code и Codex. Остальные вендоры — позже.

## Сейчас, две недели: 0.5 «Работает честно»

1. **Здоровье подключения.** отдельные состояния «конфиг записан», «helper жив», «первый хук пришёл», «Codex ждёт доверия в `/hooks`». Кнопка «Тестовый запрос». Чек-лист при первом запуске (S–M).

    - Проверка: Чистая установка до первого реального разрешения у пяти человек без подсказок; меряем время.

2. **Поиск сессий.** старые продолженные треды Codex, восстановление после подмены или усечения файла, без очереди сканирований (M).

    - Проверка: Регрессионные фикстуры; после холодного старта все живые сессии видны за 10 с.

3. **Доставка ответа.** обратный отсчёт до 100 с, статусы «отправлено», «доставлено», «истекло», учёт ошибки записи (M).

    - Проверка: Клик на границе таймаута, выход из приложения, сон: ни одного ложного «доставлено» и ни одного разрешения без клика.

4. **Безопасное удаление и мелочи.** zap сообщает об ошибке и не удаляет инструмент восстановления; конфиги JSONC; ротация `decisions.jsonl` (S).

    - Проверка: Zap при сломанном конфиге одного вендора не оставляет висячих хуков молча.

5. **Правда в документах.** Codex Always убрать из README (доделываем в 0.6), отметить вопросы и планы как только Claude, CHANGELOG 0.4.0, название; воркеры под родителем остаются (S).

    - Проверка: Каждому обещанию README соответствует строка в коде.

## Дальше, один-два месяца: 0.6 «Ставится за минуту»

6. **Установка без нотаризации.** свой tap в brew и пошаговая инструкция для первого запуска с картинками. Developer ID не покупаем, поэтому основной `homebrew/cask` недоступен (S).

    - Проверка: Новый человек ставит по инструкции и доходит до первого запроса без вопросов.

7. **Честное «готово» и «ждёт».** фоновые сабагенты не дают ложного «ждёт», тишина не значит «готово», в тосте видны «не сделано», упавшие тесты и коммит именно этой сессии (M).

    - Проверка: Долгая тихая команда и убитый процесс не получают тоста «успех».

8. **Точный переход.** Codex CLI и вкладки терминала, понятная подпись, когда открылась только папка; несколько мониторов (M).

    - Проверка: Две сессии одного проекта в разных окнах открываются правильно.

9. **Бюджет производительности.** замер на 200 сессиях и 10 000 архивных файлов, FSEvents вместо опроса раз в 5 с (L).

    - Проверка: CPU в простое ≤2% ядра, память ≤200 МБ, новые состояния видны за 5 с.

10. **Codex «Разрешать всегда» доделан и возвращён в README** (M).

    - Проверка: Правило срабатывает на втором одинаковом запросе Codex.

11. **Проверка обновлений.** всегда включена, выключается в настройках. В README: «единственный сетевой запрос — проверка версии на GitHub» (S).

    - Проверка: С выключенным переключателем Little Snitch не видит ни одного запроса.

12. **Иконки нейросетей в баре.** выбор из встроенного набора и SF Symbols для каждого вендора, независимо от темы (S).

    - Проверка: Смена темы не сбрасывает выбранные иконки.

13. **Запуск.** демо на 30 с (несколько сессий, запрос, ответ из чёлки, возврат в чат), Show HN, r/ClaudeCode, awesome-claude-code. После пунктов 6 и 7 (S).

    - Проверка: Скачивания релиза и установки через cask; звёзды вторичны.

## Потом, три-шесть месяцев, если 0.5 и 0.6 сработали

- **Слой адаптеров для двух вендоров и набор фикстур по версиям** Claude и Codex (L). Сейчас `Vendor` — перечисление на два случая и около 60 ветвлений по коду. Изменения формата логов должны ловиться тестом, а не молча прятать агентов.
- **Пробный переход на Codex app-server** (M–L). Он сообщает `waitingOnApproval` и `serverRequest/resolved`, то есть настоящее подтверждение ответа, а не догадку по логам. Если для подключения придётся перезапускать чужие сессии, прекращаем.
- **Предпросмотр последствий** (M): перед `git push` показываем уходящие коммиты, перед `rm` — число файлов.
- **Конфликт файлов между агентами** (M): два агента правят один файл — предупреждаем.
- **Прогноз лимита** (S): «при таком темпе лимит кончится в 16:40».
- **Телефон и удалённые одобрения**: вернёмся к вопросу после 0.6.
- **Лимиты и расходы без притворства** (M): источник и возраст данных, «неизвестно» вместо нуля, дневной расход виден и без лимитов подписки.
- **Остальные вендоры** (L): владелец планирует их добавить после двух текущих. Первым кандидатом выглядит OpenCode: у него есть событие `permission.asked` и API ответа. У Gemini CLI разрешения только для наблюдения, у Cursor `ask` не применяется.

## Не делаем

- Оркестрацию, worktree и запуск агентов: это Conductor и cmux.
- Новые темы, маскоты, аналитику уровня биллинга, Intel, Windows и Linux в этом цикле.
- Правила-стражи, журнал решений в интерфейсе, дифф перед разрешением правки, детектор «застрял», «пока вас не было», палитру и режим «не мешать».

Воркеры под родителем остаются. Телефон и другие вендоры отложены, как указано выше.
